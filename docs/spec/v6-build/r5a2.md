#### The invariants of an `affixed_number` block

**C6-8.** Nine rules govern a block of this role. Seven are decidable
from a parsed document; AF6 fixes a meaning rather than a predicate;
AF-P is marked *producer*, true or false of a PRODUCER and checked by
the producer-side tests, because a loader holds one document and never
the table it describes.

| id | statement |
|---|---|
| AF1 | `affix_prefix` and `affix_suffix` are not both the empty string |
| AF2 | `small_cell_floor <= n_affixed <= n_present` |
| AF3 | `n_affixed` is at least the parse-line count of `n_present` |
| AF4 | `n_core_numeric + n_core_out_of_range + n_core_contradictory + n_core_not_numeric == n_affixed` |
| AF5 | `n_core_numeric >= 1` |
| AF6 | `integer_valued` is a fact about the CORES and is what a consumer routes on, never the role name |
| AF7 | every quantitative key of C6-6 obeys the invariant this document gives it on `count`/`continuous`, read over the cores under the substitutions below |
| AF-P | *producer*: the pair is the pair the source cells wore, and every core is the cell's longest-then-leftmost parsing substring |
| AF-R | every column whose `role` is `affixed_number` carries the remark form below |

**AF3's count is a COUNT** - the count `minimum_parse_rate` fixes over
`n_present`, applied as a count and never as a compared share. A block
whose pair never cleared the detection line cannot conform, whatever
else it publishes. **AF5 is Q3 read over the cores**, on its own line
so that a consumer need not derive it through AF7. AF2's lower bound
is where a loader checks what detection decided.

**AF7's substitutions, written out, because a rule read two ways is a
rule two implementations spell two ways.**

| where a `count` invariant names | this role reads |
|---|---|
| `n_numeric` | `n_core_numeric` |
| `n_out_of_range` | `n_core_out_of_range` |
| `n_contradictory` | `n_core_contradictory` |
| `n_present` and `n_rows` | themselves, unchanged - they answer for the column's CELLS on every role |

Concretely: Q2 reads `n_used_in_statistics == n_core_numeric` and
`n_left_out_of_statistics == n_present - n_core_numeric`, cells
wearing no pair included; Q9 reads `numeric_share == (n_core_numeric +
n_core_out_of_range + n_core_contradictory) / n_present`; Q10 reads
`n_negative_unrepresentable <= n_core_out_of_range` and `<=
n_negative`; Q11 reads `n_zero <= n_core_numeric`; P1 reads
`sum(numeric_styles.values()) == n_core_numeric`; and
`fraction_widths` is a census of the `decimal`-styled cores, its P5.a
through P5.c, P6 and P7 read over that population. Q4 through Q8 name
no census count and are read exactly as this document states them.

**The substitution reaches the three numeric-looking cell counts and
not `n_numeric` alone, because Q9 and Q10 name the other two.** A
hundred-cell milligram column of ninety `5 mg`-shaped cells and ten
`-1e999 mg` cells publishes `n_out_of_range: 0` - no complete cell of
it reads as a number, well-formed or otherwise - beside
`n_core_out_of_range: 10` and `n_negative_unrepresentable: 10`. Read
over the cell census Q10 is `10 <= 0` and a conforming document is
refused, and Q9 computes `(90 + 0 + 0) / 100` for a column every
present cell of which carries a numeric-looking core.

**It stops there, and the population stays `n_present`.** C6-6
publishes `n_left_out_of_statistics` as present cells that did not
contribute a core, cells wearing no pair included, and `numeric_share`
as a share of the present cells; reading `n_affixed` in place of
`n_present` would make both keys answer for a narrower population than
the words this document gives them, and no rule here says they do. X2
closes over the CELLS on this role as on every other; AF4 is the core
census's own closure, standing beside X2 and never in place of it,
because a present cell that wore no pair has no core to classify.

**Why AF-P is a producer obligation.** Two documents can satisfy AF1
through AF7 and disagree about what the source held: nothing in a
description says `mg` was the text the cells wore rather than a text a
producer chose, or that the split was taken at the longest-then-
leftmost substring rather than another. The split rule is a total
order on candidate substrings precisely so that this obligation is
checkable against a TABLE - one table, one answer - even though it is
not checkable against a document.

#### The publication class

**C6-9.** `affixed_number` is a RANGES-class role: order statistics
computed from the cores appear and no spelling of a cell appears -
with ONE named exception, confined by section 6.11's matrix to exactly
two keys, `affix_prefix` and `affix_suffix`, which carry the shared
affix text.

**The exception is an exception, not a fourth class.** A fourth class
would have to be given a meaning everywhere the three are enforced;
this is held to two cells of one column of one matrix. **No key of any
ranges-class role but those two may carry a spelling.** The labels
class is untouched by it, and the nothing class's "no value, no
spelling, no fragment of one" sentence is untouched by it.

**The class governs the column's VALUES.** It does not reach
`missing_by_class`, whose keys are this format's own words, and it
does not silence `missing_by_source`: this is not a nothing-publishing
role, so an undeclared block of it names its absent spellings under
the floor exactly as a `datetime` block does.

**The floor rule that governs the pair.** The pair's cell count clears
`small_cell_floor` at DETECTION - it is the role's own entry condition
- so publishing a floor-clearing spelling is constitutive of the role,
and a published pair is always a floor-cleared fact. There is no
suppression path for the pair, no `(withheld)` spelling of it, and no
block of this role in which it stands below the floor: a column whose
pair cannot clear the floor under the recorded settings takes a later
rule instead, and where that rule is `free_text` it says so in its own
evidence through the affix clause of `remark_no_reading_fits`. Because
the floor may be RAISED without limit, the direction is stated
plainly: a raised floor or a small table withholds this role rather
than publishing a below-floor pair.

**What ranges membership costs here, named because it is new.** The
core ladder's two ends are exact values of real cores, published
floor-free under the endpoint policy every ranges-class role carries.
Both the pair and the core distribution are disclosure no earlier rule
of the order would have produced for this column, so a column that
reached `free_text` before this role existed now publishes two exact
numbers beside them, and the disclosure delta prices all of it.

**The `--identifier` route works by leaving this role, not by
narrowing it.** The declaration is decided at rule 2 of C6-1's order
while this role is tested after `categorical`, so a declared column
reaches `empty` or `identifier` and no other role (A3) and the
structural override - a column whose `structural_role` is `identifier`
is a nothing-publishing column whatever its `role` (C6-52) - never
meets a block of this role. What the declaration buys is that nothing
of the column is published: not the pair, not a core statistic, not
the remark that would have named the route.

#### The keys forbidden on this role

**Every key not marked for `affixed_number` in section 6.11's matrix
is FORBIDDEN on it** (C6-53), and a loader refuses an unknown key
naming both the key and the column. A conforming block's key set is
exactly the twenty-two universal keys plus this role's own twenty-two,
and nothing else - including a key this document defines for another
role. "Forbidden" is the half of a contract a loader can enforce only
where it is written down, so the thirty-three other rows of that
matrix are named here. The group headings are a reading aid; the key
names are what is normative, and a key named in neither column of this
section is governed by C6-53's residual rule.

| group | keys forbidden on `affixed_number` |
|---|---|
| the label keys | `levels`, `suppressed_levels`, `suppressed_rows`, `suppressed_level_counts`, `level_ceiling` |
| the datetime keys | `format`, `resolution`, `resolution_mix`, `time_precision`, `subsecond_digits`, `datetimes_read_at`, `earliest`, `latest`, `earliest_utc_offset`, `latest_utc_offset`, `date_percentiles`, `utc_offsets`, `n_unparsed` |
| the clock keys | `clock_form`, `clock_percentiles` |
| the unrepresentable keys | `n_whole`, `n_fraction`, `n_whole_unknown`, `n_positive`, `n_sign_unknown` |
| the length pair | `min_length`, `max_length` |
| the text and code keys | `all_whole_numbers`, `length`, `words`, `n_all_digits`, `n_code_alphabet`, `n_distinct_by_occurrences` |

`n_negative` is the one name this role shares with
`numeric_unrepresentable` and it is not on the list above: one key with
one meaning, asked of the present cells there and of the cores here.

Two of the thirty-three a reader can build an argument for.
`n_unparsed` is forbidden although this role tolerates stragglers:
those cells are `n_present - n_affixed`, and a key restating a
subtraction is a key two implementations can disagree about.
`min_length` and `max_length` are forbidden although the cells are
text: they are the pair whose population differs by role, and
admitting them here would add a third population - cells, cores or
affixes - with no rule saying which.

#### The remark this role always carries

**AF-R.** Every `affixed_number` column carries
`remark_affixed_numbers_may_be_codes`, whose arity, rendering and
argument classes section 4.5.1 fixes and whose argument checks section
4.5.2 states: argument 1 is the block's `affix_prefix` and argument 2
its `affix_suffix`, bound positionally and character for character,
and argument 3 is its `n_affixed`. The sentence names the pair, states
how many present cells actually wore it, says the numeric parts were
described as quantities, and names `--identifier` as the route where
the column holds codes rather than measurements.

**The count is in the sentence, and the sentence must not say "every
value."** A rendering opening "EVERY value in this column is written
as..." claims more than the role requires: the detection rule admits
stragglers up to the parse line, so a hundred-cell column with
ninety-nine affixed values and one plain number conforms and the
sentence is false of the hundredth. A remark whose whole job is to let
somebody recognize their own column must not misdescribe it.

**Why it is unconditional.** No test of the values can separate an
opaque token family from a measurement. A prefixed code column
(`A-101`, `A-102`, ...) that published nothing before now reads as
quantities with a published distribution over its numeric parts, and
repeating decimal-cored tokens defeat every conditional remark anyone
drafts - the inference three withdrawn attempts failed at. The choice
is therefore between telling every such column's owner and telling
none, and this format tells every one: the remark fires on the role,
not on a guessable subset of it, the same tell-the-person-both-ways
posture the all-different-values remark takes, which reaches this role
in NF32's wording on its own trigger -- the NUMBERS form and not
NF34's text form, corrected 2026-08-26 with residual R-P4-21. What the misroute cannot do is take a
column away from a rule that handles it already: `V1`, `V2`, `V3`
visit labels stay `categorical`, because `categorical` runs first.
