#### 7.4.3 Invariants: the W family

**C6-114 (what the seven quantify over).** W1 through W7 are stated
over a PUBLISHED LEVEL ENTRY — one member of a block's `levels`
(section 6.3.1) — and over the two spelling maps that entry holds.
None of them names a publishing role. Only W1 reaches outside the
entry, and only to its complement: the two keys are forbidden on every
block that publishes no `levels`. So every block that publishes
`levels` binds all seven identically, and not one of them is restated,
widened or excepted for any role — `long_tail_labels` included, which
publishes `levels` under the shared label shape of section 6.3 and
therefore takes the seven exactly as they stand. The floor they read is
`small_cell_floor`, the setting of section 4.4, so each binds at
whatever value the document records.

**Invariant W1 (parent binding).** Every variant is bound to one
already-visible parent label: the two keys are forbidden on a withheld
parent, which has no entry to carry them, and on every non-label role.
The disclosure argument rests on it — what this addition publishes is
bounded to the spelling forms of labels the profile ALREADY publishes,
so a label the description refuses to name has no spelling named
either.

**Invariant W2 (each variant folds to its parent).** Trimming a
`variants` key and case-folding it yields exactly the entry's `label`.
A key that folds to anything else is a refusal: it would be a spelling
of some OTHER label filed under this one. The fold is the folded
identity of section 2.3 — the same trimming and the same Unicode
`casefold()` that produced the label — so W2 and B1 read one operation.

**Invariant W3 (no variant exceeds its parent).** Every value of
`variants` is at most the entry's `count`.

**Invariant W4 (the counts close exactly).**
`sum(variants.values()) + sum(key × value for variants_withheld)`
`== count`, each `variants_withheld` key read as the base-ten number it
spells. Nothing about a published label's rows is unaccounted for.

**Invariant W5 (the floor governs a variant like any published
label).** Every value of `variants` is at least `small_cell_floor`.
Every key of `variants_withheld`, read as a number, is between 1 and
`small_cell_floor - 1` inclusive. The reason is the disclosure
argument: no variant crosses the boundary that a whole label would not,
because each variant is governed by the same floor as any published
label. Invariant S13 draws the consequence at a floor of 1, where the
second range is empty.

**Invariant W6 (variant keys are distinct).** They are object keys, so
this is a property of the JSON, but it is stated because two spellings
that differ only by a character the canonical form does not distinguish
would be one key and must not be produced as two.

**Invariant W7 (at least one spelling exists).** `variants` and
`variants_withheld` are never BOTH empty on the same entry, because a
published label covers at least `small_cell_floor` rows and every row
was written some way.

**C6-115 (what a loader decides, and what it cannot).** Six of the
seven are decided by inspecting one document. A loader refuses W2, W3,
W4, W5 and W7 BY NAME: W2 by trimming and folding each `variants` key
and comparing it with `label`, and the other four by arithmetic inside
the one entry, against that entry's `count` and the recorded floor. W1
it also decides, but not by name — the level entry's exact four-key set
and the forbidden-key matrix (sections 6.3.1 and 6.11) leave the two
keys nowhere else to stand, and the refusal a reader meets names the
offending key. W6 is NOT visible in the parsed value: a parse keeps one
value for a repeated key, so the duplicate is gone before any rule of
this family could read it. It is decided by the canonical round trip
alone, which refuses a duplicated key for the reason stated with that
check (R10).

What no loader decides is whether the two maps describe the column they
claim to. That each `variants` key is the spelling the source file
held, byte for byte (section 7.4.2), and that the two maps between them
close over exactly the rows of the real label (W4), is checkable only
against the table, so both are met where the description is
made. A loader holding one document checks that the description is
consistent with itself; it can never learn that a producer named a
spelling the file never held.

**Rules about these two keys that other sections own**, named so no
reader looks for them twice: their wire shape, the exact-storage rule
for a `variants` key, and the validity of `{}` on either map together
with the requirement that both keys stand even when empty (section
7.4.2); the level entry's four keys and the shared label invariants B1
through B8 (sections 6.3.1 and 6.3.2); the multiplicity-map form, and
M1 and M2 as they bind `variants_withheld` (section 5.3); what a floor
of 1 empties, and why a key of `variants` is never read as one of this
format's own words (S13); and both dispositions — EXACT-OBSERVABLE —
with the consequence for raw `n_distinct` (section 9).
